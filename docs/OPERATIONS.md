# 운영과 인증 기준

스터디 운영과 인증 기준을 설명합니다. 설치와 키 설정은 [배포 안내](DEPLOYMENT.md), 동작 확인 절차는 [검증 방법](VERIFICATION.md)을 참고하세요.

## 계정과 스터디

GitHub 계정으로 로그인한 뒤 스터디를 만들거나 초대 링크로 참여합니다. 계정은 전역으로 관리하고, 소속과 운영자 역할은 스터디마다 따로 관리합니다. 로그인이 되어 있어도 다른 스터디의 회차, 사진과 코드를 볼 수는 없습니다. 정원은 운영자를 포함해 1~20명, 계정당 운영할 수 있는 스터디는 최대 5개입니다.

운영자는 **저장소 및 멤버**에서 7일간 유효한 초대 링크를 만들고 재발급할 수 있습니다. 재발급하면 해당 스터디의 이전 링크를 통한 신규 가입이 만료되며, 이미 참여한 멤버는 유지됩니다. 가입 완료 시에도 링크 유효 기간과 정원을 확인합니다. GitHub 아이디를 사전 등록할 필요는 없으며 직접 등록 기능도 선택 항목으로 남아 있습니다.

초기 인스턴스의 GitHub App 소유자는 config의 `OWNER_GITHUB_ID`로 확인합니다. 로그인한 계정의 GitHub 숫자 ID로 소속을 식별하므로 표시 이름이나 아이디 변경으로 다른 사람의 권한을 넘겨받지 않습니다.

## 운영 규칙과 회차

| 방식 | 운영 기준 |
| --- | --- |
| 공통 문제형 | 문제 1~30개와 LeetCode 수를 설정합니다. 나머지는 프로그래머스입니다. 등록한 문제와 일치하는 새 풀이만 인증합니다. |
| 자율 목표형 | 개인 목표 1~30문제와 인정 플랫폼을 설정합니다. 기간 내 서로 다른 문제의 정상 인증 수로 목표를 계산합니다. |

요일 지정 또는 기간마다 날짜 지정으로 마감일을 정하고 한국 시간의 기본 마감 시각을 설정합니다. 운영자가 기간을 등록해 공개하며 주간 회차가 자동 생성되지는 않습니다. 표시한 마감 분의 끝까지 정상으로 인정합니다. 예를 들어 화요일 23:59 마감이면 화요일 23:59:59.999까지입니다.

각 회차는 등록 당시 규칙과 마감을 보관합니다. 스터디의 기본 규칙 변경은 새 회차부터 적용하며, 기존 회차의 문제 수와 운영 방식을 바꾸지 않습니다.

## GitHub 자동 인증

저장소 연결은 개인 계정에 속합니다. 사용자가 앱 설치에서 선택한 저장소 중 플랫폼별로 연결을 저장하며, 그 계정이 참여한 스터디의 최신 공개 회차들과 대조합니다. 코드와 메모는 다른 스터디에 자동으로 공유하지 않습니다.

1. 연결한 저장소의 기본 브랜치에서 커밋을 조회합니다.
2. GitHub가 식별한 작성자 숫자 ID가 멤버 ID와 같아야 합니다.
3. Git committer 시각이 공개일 00:00(KST) 이후여야 합니다. 기존 파일이 있다는 이유만으로 인정하지 않습니다.
4. 소스 파일에 실제 코드 변경이 있어야 합니다. 문서나 통계만 바꾼 커밋과 병합 커밋, 삭제나 내용이 그대로인 이름 변경은 제외합니다.
5. LeetHub v2/백준허브의 소스 폴더와 같은 커밋 README의 정확한 문제 URL을 확인합니다. 제목이 비슷하거나 추천 문제 링크만 있다고 인정하지 않습니다.
6. 공통형은 출제 문제 ID와 대조합니다. 자율형은 허용 플랫폼의 문제를 발견하고, 기간 내 정상 인증을 목표에 반영합니다.

인증은 회차, 멤버와 문제마다 한 건입니다. 같은 문제를 사진과 GitHub로 중복 제출해도 목표 수가 중복 증가하지 않습니다. 공통형의 늦은 인증은 지각으로 표시합니다. 자율형은 마감 후 GitHub 풀이를 목표에 반영하지 않으며 지각 사진은 기록만 보관합니다.

이것은 GitHub 기록을 근거로 하는 스터디 인증입니다. 플랫폼의 실제 정답 판정이나 부정행위를 독립적으로 증명하지는 않습니다. README가 없는 저장소, 지원하지 않는 구조, 변경 파일이 100개 이상인 큰 커밋은 사진 인증을 사용합니다. 같은 코드로 다시 풀어 확장 프로그램이 새 커밋을 만들지 않는 경우도 사진으로 제출할 수 있습니다.

### 확인 주기와 누락

서명을 검증한 push 수신 후 작은 묶음으로 확인합니다. 누락된 알림은 5분마다 가장 오래 확인하지 않은 저장소 2개씩 재확인합니다. 저장소 10개라면 한 바퀴에 약 25분이 걸리며 사이트를 닫아도 실행됩니다. 무제한 즉시 확인을 보장하는 구조는 아닙니다.

한 번에 커밋 3개, 페이지당 10개, 최대 30페이지로 제한하고 다음 위치를 저장합니다. 기록이 많으면 여러 번에 걸쳐 처리합니다. 기본 브랜치, 작성자와 확장 프로그램 구조와 화면의 동기화 오류를 확인하고, 필요하면 **지금 확인** 또는 사진 인증을 사용합니다.

## 사진 인증과 OCR

문제 이름/주소와 최종 통과 결과가 함께 보이는 캡처를 첨부합니다. 자율형은 먼저 플랫폼과 문제 링크와 제목을 등록합니다. 문제 정보를 등록하는 것만으로 인증되지는 않습니다.

Tesseract.js 7과 한국어와 영어 모델은 브라우저에서 실행합니다. 외부 OCR API로 사진을 보내지 않으며, 제출할 때 사진과 인식 결과를 서버에 저장해 해당 스터디 팀원에게 보여줍니다. 입력은 JPG, PNG 또는 WEBP 1장, 최대 5MB이며 저장 전에 350KB 이하 JPEG로 압축합니다.

- 문제 식별과 최종 통과 문구가 일치하고 인식 점수가 80 이상인 경우 OCR 대조 인증을 처리합니다. 샘플 테스트만 통과한 것은 최종 통과로 보지 않습니다.
- 불분명한 인식, 다른 문제와 실패 문구 등은 자동 인증하지 않고 팀원 확인 대기로 저장합니다. 확인 대기는 인증 수, 목표와 잔디에 포함하지 않습니다.
- 제출자를 제외한 팀원 한 명이 원본을 확인해 승인과 반려합니다. 반려 이유, 검토자와 시각을 기록하며 승인 시 원래 제출 시각으로 마감을 판정합니다.

다크 캡처는 원본과 밝기 보정과 확대 결과를 비교합니다. 원본에서 실패가 읽혔다면 보정 결과에 통과가 보여도 자동 인증하지 않습니다. 작은 한글과 흐린 숫자는 계속 잘못 읽을 수 있어 원본 화면 확대 또는 팀원 확인이 필요합니다.

OCR은 제출한 글자를 대조하는 보조 수단입니다. 서버에서도 문제와 통과 조건을 다시 비교하지만, 클라이언트가 보낸 OCR 정보 자체가 조작 방지나 본인이 이번 기간에 풀었다는 것을 독립적으로 증명하지는 못합니다. 본인이 직접 다시 풀었다는 확인을 함께 받습니다.

사진 원본은 90일 보관하고 인스턴스 전체 사진 저장량을 100MB로 제한합니다. 만료되면 원본만 정리하고 인증 기록과 메모는 유지합니다. 오래 보관할 사진은 만료 전에 직접 내려받습니다.

## 인증 현황과 회차 관리

공통형은 문제와 팀원별 인증 표, 자율형은 팀원별 진행률과 펼쳐 보는 인증 내역을 사용합니다. 일별 잔디는 한국 시간의 커밋/사진 제출 시각으로 집계하며 같은 회차와 문제를 한 건으로 셉니다. 목표 현황과 미인증 목록을 카톡에 붙여 넣을 내용으로 복사할 수 있습니다. 미인증은 인증 기록이 없다는 뜻이며 실제로 문제를 안 풀었다는 증거는 아닙니다.

지난 회차는 **지난 문제 기록 등록**에서 문제 목록만 보관할 수 있습니다. 번호가 없으면 출제일로 구분하고 없는 마감은 미기재로 표시합니다. 이 기록은 인증, 잔디와 출제 순서에서 제외하며 당시 인증을 임의로 복원하지 않습니다. 등록자와 출제자는 따로 기록합니다.

운영자는 제목, 출제자, 문제와 마감을 수정할 수 있습니다. 인증된 문제의 교체는 차단하고 인증 시각은 보존합니다. 미인증 문제 교체는 원래 공개일부터 다시 확인합니다. 동시 수정과 규칙 버전 충돌은 덮어쓰지 않고 재확인을 요구합니다.

## 풀이 코드와 메모 공유

본인이 인증한 문제만 코드, 언어와 메모를 저장하고 공유할 수 있습니다. GitHub 인증이면 인증 당시 커밋의 해당 코드 파일을 불러오고, 사진 인증이면 직접 입력합니다. 비공개 저장소도 작성자가 선택해 저장한 내용만 해당 스터디에서 공유합니다. 다른 스터디나 비로그인 방문자에게 자동으로 공개하지 않습니다.

작성자는 수정과 공유 중지를 할 수 있고, 중지 후 본인 내용은 보관합니다. 코드는 24,000자 이내이면서 64KB를 넘지 않아야 합니다. 메모는 4,000자까지 저장할 수 있습니다. 공유 여부는 인증 수와 잔디에 영향을 주지 않습니다.

## 세션과 운영

자동 로그인 선택 시 최대 30일, 해제 시 브라우저 세션 쿠키와 서버 최대 8시간입니다. 30일은 로그인 시점부터 계산하며 토큰 갱신으로 연장하지 않습니다. HttpOnly와 SameSite=Lax 쿠키를 사용하고 HTTPS에서는 Secure를 적용합니다. 로그아웃은 해당 기기 세션을 제거하고 같은 브라우저의 다른 탭에도 반영합니다.

GitHub 토큰과 앱 비밀키는 서버에서 암호화하며, 키는 Cloudflare Secret으로 보관합니다. 앱은 저장소 읽기 권한을 사용합니다. 무료 운영 한도, 업데이트 및 복구 절차는 [배포 안내](DEPLOYMENT.md)에 따릅니다. 운영 DB에 테스트용 팀원, 회차와 사진을 넣지 않습니다.
